What each phase does

1 · Discover

  • Auto‑pick the top‑10 trending topics inside your seed areas
  • Pull papers & patents per topic: arXiv ✅, Semantic Scholar, OpenAlex, Hugging Face Papers, USPTO patents
  • Rank by recency, citations, code available
Done: arXiv search + PDF text · To do: topics, more sources, ranking

2 · Distill

  • Split each paper into 5–10 technical concepts ✅
  • Turn each concept into a claim card: what to change, claimed gain, test setup, effort, risk
  • Plain technical language with evidence quotes — no marketing / social‑post style
  • Merge the same idea across papers
Done: concept split · To do: replace the post‑style prompt with structured claim cards

3 · Match & Plan

  • Profile your project: stack, hot paths, benchmarks, metrics
  • Score claims: fit × expected gain ÷ effort; flag blockers (“needs CUDA”, “needs GPU cluster”)
  • Experiment spec: hypothesis, baseline, workload, runs, success bar, guardrails
✋ Gates: pick 1–2 claims · approve spec

4 · Build & Run

  • Coding agent works on a new branch, adds the idea behind a flag
  • Adds a benchmark if missing; existing tests must pass
  • Runs baseline vs variant: same machine, warm‑up, interleaved, N times
Output: branch, diff, raw metrics, logs

5 · Validate & Learn

  • Median change + 95% confidence interval
  • Verdict vs claim: Reproduced · Partial · Not reproduced · Regression
  • HTML report + PR; links Paper → Claim → Verdict in Postgres
✋ Gate: merge or drop

6 · Run continuously (later)

  • Scheduled scans for new papers on your topics
  • Auto‑triage new claims against your project
  • Weekly digest; learn which kinds of claims hold up
Output: an always‑on research radar

Guardrails & watch‑outs

Guardrails

  • Agent code lives on a branch — nothing reaches main without your merge.
  • Experiments run isolated, with time and cost caps.
  • A speed win that hurts quality counts as a regression.
  • Fair comparisons: same machine, same workload, warm‑up, interleaved runs.
  • Every verdict links back to the paper sentence that made the claim.

Watch‑outs

  • A 30B model in full precision (≈61 GB) won't fit beside macOS → 8‑bit weights. 8‑bit on Apple GPU is still maturing, so task 1 is a fit‑and‑speed test.
  • Many inference papers assume NVIDIA GPUs / CUDA kernels — labeled “not testable on Mac” up front.
  • Docker on macOS can't use the Apple GPU, so runs use an isolated venv.
  • The baseline is already 8‑bit, so quantization claims are measured against 8‑bit, not bf16.
  • Laptop benchmarks are noisy (thermal throttling) — enough runs + confidence intervals.
  • LLM cost: today it's ~1 call per concept; the new extractor makes one structured call per paper. Patents need a free USPTO PatentsView API key.
